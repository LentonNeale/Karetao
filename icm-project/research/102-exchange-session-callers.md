## Concepts met

- **Pipelined correlation versus positional reading**: the time-sync probe read the reply from the request's own transaction and so could never match a fresh request; `exchange()` matches by the `request_seq` the reply names, whichever transaction carries it.
- **Pacing inside the call**: `exchange()` sleeps before each transfer, so anything stamped before the call is stale by the pacing gap; stamp after the gap is spent.
- **One transmitter, one sequence space (R3)**: every tool draws from `process_sequencer()`; `peek()` is only safe while nothing else draws, so the probe checks `result.request_seq` before using a sample.
- **Raw versus slewed monotonic clocks (R16)**: `CLOCK_MONOTONIC` is slewed by NTP, `CLOCK_MONOTONIC_RAW` is not; the probe now stamps from the session's raw clock.
- **Contract fake versus ad-hoc fakes**: the five deleted fakes each answered every transfer their own way (one even answered every transfer with VERSION, so its tests passed without a pipeline); `FakeFirmware` enforces the firmware's rules, so a lost request now exhausts, as on the bench.
- **`sys.modules` and `@dataclass`**: loading a tool with `importlib` must register the module before `exec_module`, because `dataclass` looks the module up there to resolve annotations.

## What the change did and how it was verified

The timing harness, the link probe and the time-sync probe now clock the link only through `ExchangeSession`, and each gained (or, for the harness, moved) `--fake` onto `FakeFirmware`. `spi_device.py`, `SpiDevice`, `timing.py` (its statistics moved into the harness, their only caller) and `TimingSession` are deleted, with `test_spi_device.py`, `test_timing.py` and the five fakes (`VersionBackend`, `PipelinedBackend`, `GarbageBackend`, `FakeBackend`, `PipelinedFakeBackend`) and the harness's own `PipelinedFakeBackend`. Documents: Pi `README.md` (owner of transaction, exchange and pacing; `--fake` for all three tools), `RASPBERRY_PI_BRINGUP_V1.md` E4 and the open-observations list, `SYSTEM_VERIFICATION_MATRIX.md` rows SYS-SPI-001, SYS-TS-001 and SYS-SYNC-001, `ROUTING.md`.

Pi test count 250 before, 250 after. Removed 37: `test_spi_device.py` 13, `test_timing.py` 22, and the link probe's bad-magic and bad-CRC `version_lines` tests (decoding now happens in the session; an undecodable response is covered by `record_lines` tests). Their behaviour is kept or moved: correlation and NACK helpers (6), phases, hub delta, open bus, the four pacing tests and the corrupted-transfer case moved to `test_exchange.py`; the two seed tests moved to `test_spi_protocol.py`; statistics (4) moved to `test_spi_timing_harness.py`; identity decode, dirty build, no-reply and BAD_SEQUENCE are tested through `read_version` and the evidence-record tests; foreign NACK and foreign VERSION now have exchange tests. Dropped as no longer meaningful: `SpiDevice.transact`'s backend call, the 2-transaction reply delay (the firmware's is one, fixed by the fake), corruption on the request's own transfer still returning a reply (a lost request now exhausts, which is what the hardware does; tested), and `TimingSession`'s positional-constructor and `start_sequence` tests. Added 37: 17 in `test_exchange.py`, 2 in `test_spi_protocol.py`, 7 in `test_spi_link_probe.py`, 10 in `test_spi_timing_harness.py` (with the harness `--fake` run), 1 in `test_spi_time_sync_probe.py` (with the probe `--fake` run).

Checks on 2026-10-16 in the worktree: Pi tests 250 pass; HostTests 6 of 6; Debug build passes with the stack check (no firmware change); `doc_check` clean; each tool run with `--fake` (harness: identity read, two blocks, zero errors; link probe: VERSION verdict and snapshot exchange; time-sync probe: every TIME_SYNC accepted, where before every sample was dropped as a seq mismatch). Mutation check: making `exchange()` end on any VERSION or NACK fails the new foreign-VERSION and foreign-NACK tests.

`/code-review medium` raised eight findings. Fixed: (1) the time-sync payload was stamped before the session's pacing sleep, so it was stale by the interval; (2) the harness's identity read was unpaced; (3) the probes' DATA_READY waits were unregistered numbers, now PRM-SPI-04 through the session; (4) a sequence drawn between `peek()` and the send now drops the sample; (5) the BAD_SEQUENCE advice now lives in `NackReason.remedy()` for both tools; (8) tests added for a foreign VERSION, a request lost in its own transaction, and DATA_READY already asserted. Recorded, not fixed: (6) each harness block's new session misses the first record's round trip when `--warmup 0`, as before; each block opens its own bus at its own clock, so one session per bus stays; (7) `TIME_SYNC_CHARACTERISATION_EVIDENCE.md` and `TIME_SYNC_VALIDATION.md` still name `SpiDevice`; ruling R16 retires both with TIME_SYNC (#45). Rechecked after the fixes: as above.
