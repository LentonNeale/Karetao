## Concepts met

- **Priority inheritance** (FreeRTOS mutex): a mutex records its holder task and may raise that task's priority while a higher-priority task waits; the give is where the boost is undone, so only the holder task may give. A binary semaphore has no holder and can be given from an ISR. `queue.c:1133`, `tasks.c` `xTaskPriorityDisinherit`.
- **FromISR priority ceiling**: `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 5`; an ISR may call FromISR kernel functions only at numeric priority 5 or higher (less urgent). The I2C1 lines sat exactly on the ceiling. `FreeRTOSConfig.h:144`, `FIRMWARE_ARCHITECTURE.md` §7 "Priority rule".
- **Two-stage interrupt gate**: the NVIC enable lets a request through; the peripheral's own CR2 bits (ITEVTEN, ITBUFEN, ITERREN) decide whether a request is raised. Blocking HAL calls never set them. `stm32f4xx_hal_i2c.c:1733`.
- **Fail-stop versus fail-reset**: `configASSERT`, `Error_Handler`, the fault handlers and the CSS NMI all loop forever; a watchdog would turn that into a reset. `FreeRTOSConfig.h:156`.
- **Dormant versus dead**: dead code has no caller and is dropped by the linker (`SubmitAsync`); dormant code is linked and armed but its trigger never occurs (the I2C1 handlers). Both hide behaviour.
- **Software shadow of hardware state**: a cached register value can only agree with the device when nothing has gone wrong; the device's own read-back is the only truth. `tca9548a_mux.c:29`.
- **CubeMX `USER CODE` blocks**: hand-written code that regeneration preserves. The I2C1 NVIC enable and handlers live in them, so this change edits them by hand and proves it with a headless regeneration whose diff is empty.

## What the change did and how it was verified

A delete-only diff. `i2c_manager.c` lost the async path (`SubmitAsync`, the four HAL callbacks, the ISR dispatch queue, the event hook, queue and notify setters), the fault handoff and `I2CManager_Process` (nothing could set the pending fault once the error callback was gone, so the main-loop call in `main.c` went too), `MasterRead`, `GetHandle`, and `MasterWrite` (dead once its only caller `TCA9548A_SelectMask` went; found by the review). The I2C1 NVIC enable and the two IRQ handlers were deleted from their `USER CODE` blocks; a headless CubeMX regeneration from the unchanged `.ioc` then left the `Core/` diff showing only those deletions, which proves the edits are in preserved blocks and nothing else moved. The mux lost `SelectMask`, `SelectChannel`, the two cache getters, the cache itself and `TCA9548A_MAX_RETRIES`. `AS5600_RawToDegrees` and `SensorLatestValue_MarkStale` went. The six little-endian helpers that existed twice now live once as `static inline` functions in `App/Inc/le_bytes.h`, and the CRC module's two byte helpers call them. The stack-check config lost its `indirect I2CManager_DispatchEvent` entry. The host test scaffolding for the async path (stubs for `_IT`, `GetError`, `xSemaphoreGiveFromISR`, `xQueueSend`, `xTaskNotify`, the `queue.h` stub) went with it; the removed argument checks were re-pointed at the live functions.

Checks: Debug and Release builds with no warnings, stack check OK in both (`defaultTask` 732 of 2048 B Debug, 624 B Release; unchanged from before, since the moved helpers replace same-sized statics); HostTests 6 of 6; Pi tests 229 OK; `doc_check` clean; a grep for every removed symbol over firmware, tests, tools, `Documentation/` and the reference notes finds none.

Review (`/code-review high`): seven findings, none a correctness bug. Fixed: `MasterWrite` newly dead (removed, test re-pointed); `I2C_MANAGER_CONTRACT.md` internally inconsistent (as-built sentences added to Lifecycle and Diagnostics); two reference notes citing deleted lines (`freertos-kernel/config-in-use.md`, `stm32f4-hal-cmsis/version-and-usage.md`, rows removed and the moved citation repointed); the `le_bytes.h` comment claiming nothing is added to the call graph (false at -O0, reworded); the CRC module's duplicate u32 encoder (now calls `LeBytes_*`); `volatile` on task-only state (dropped, with a comment). Deferred with reason: `health_monitor.c` hand-declares four `I2CManager_*` prototypes instead of including the header. It is pre-existing, and the fix needs `sprint1_protocol_tests` to gain the stub include path (the header pulls in `stm32f4xx_hal.h`), which is not a delete-only change; noted for #80 or the next tidiness pass.
